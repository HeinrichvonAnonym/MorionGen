# K4 GPU 工程化：CPU 算法一致性

本轮以 CPU 算法行为保持和执行成本为验收主线。CPU/GPU 同时相对原动作失败作为共同难例记录；迁移失败由 CPU/GPU 差异、覆盖、选择及回退变化决定。原独立 torch_gn 保留为历史算法实验。

模块分为算法契约、私有二进制协议、常驻模型计算、批量有限差分、请求分组及独立一致性检查。首个实现保留原 OpenSim 环境 SciPy 1.17.1 控制决策，将 FK 发给独立 Torch 环境；两环境版本不同，因此完整求解控制尚在 CPU。自动微分与原 GPU Gauss–Newton 未混入一致性路径。

每帧有限差分按原边界和步长批量计算；两个常规初值可并行，结果按原顺序参与选择，额外初值仍由原条件触发。整段残差及稀疏雅可比复用原 CPU 定义。模型驻留、按请求分组和线程独立的末次旋转状态分别封装。

## 计算消融与完整窗口证据

32 帧固定模型 FK 四因素对照采用相同请求/回读边界，冷调用一次、预热后三次。逐算子执行预热中位数34.20 ms；CUDA Graph为7.30 ms；仅批量坐标转换33.51 ms；两者组合5.07 ms。组合相对逐算子约6.8倍，峰值显存约34 MiB（Torch分配器口径，另有上下文开销）。模型及进程启动约3秒，另列。原CPU14 worker并行，尚未进行公平14-worker吞吐比较。

批量顺序、填充及分块检查通过；对应直接耦合定义的OpenSim位置最大差7.11e-16 m、旋转4.03e-16 rad。初次诊断误用额外assemble的FK作位置oracle，差1.88e-7 m；保留该记录。对照改为与求解内部同语义的直接耦合，assemble差异作为附加数据单列，未修改原CPU模型或求解算法。

000 Kimodo的150帧：原CPU策略＋GPU计算76.16秒，含设备启动81.12秒；299个初值TRF求解约73.55秒。相对冻结CPU最大原生位置差0.02188 mm，方向最大约0.00265°，但45帧初值选择不同，严格一致性未通过。原生/导出、D/R时钟的F-R P95差最大：位置1.262e-5 cm、角度2.782e-5°、变化率7.931e-4°/s，均在迁移容差内。初值选择差异仍单独阻塞；双方准确度达标不消除此项。

008 MotionLCM position_trajectory的100帧：同一CPU有界Gauss–Newton与LSMR控制，GPU计算145.46秒；FK请求往返仅2.45秒，当前主要成本仍在CPU求解控制及线性子问题。原生最大位置差9.02e-14 m；原生和实际导出点/方向、输入支持的旋转、D/R时钟F-R差值、覆盖及回退步骤均通过。两边20次函数评价、9次雅可比，保留同一projected-gradient回退过程。该例给出完整窗口迁移证据，尚不构成全部算法资格或公平加速结论。

多初值并行的4帧实验比单控制流组合更慢（3.22 vs 2.65秒，均含图捕获但不含进程启动），保留为消融项。主面板采用顺序CPU策略＋批量导数＋CUDA Graph＋批量坐标转换。有限差分诊断首帧残差差1.27e-14、同模板雅可比最大差2.44e-9；临界最优值选择对后续数值路径敏感，此证据不足以断言CPU有实质错误。
