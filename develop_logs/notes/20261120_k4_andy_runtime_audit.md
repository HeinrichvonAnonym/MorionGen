# Andy头胸测试耗时核查

这轮需要检验实测头胸重构，同时保留冻结CPU候选及D-only选择规则。当前慢的主因是全身提前接受条件持续阻止退出搜索，再叠加Andy只有一个数值worker。物理评分已经隔离模板先验，但运行时选择器仍评价整个模板身体；这一接入边界带来了大量与头胸验收目标不同的计算。

## 当前证据

核查时运行约8.5小时，完成9/600路，9路光学头胸验收均通过，执行失败0。9路来自A000的八格式和A001的MotionLCM，只有两条原始记录，不能解释为9个独立动作样本。

- 9路全部走到全池回退，每路实际访问14个候选，共126个。没有触发提前接受。
- 126个已访问候选均通过原生/实际导出及D/R时钟的光学头胸验收；每路第一个候选也通过。
- 每路耗时约46.3～59.8分钟，中位数55.7分钟。根据开始时间、拟合回执和结束时间估算，冻结运行时阶段共469.5分钟，后续独立评分/回读等约12.4分钟，运行时阶段占97.4%。这是文件时间边界估算，不是函数级剖析。
- 全部9路的候选中，肩线方向及变化率均出现D-only门槛失败；骨盆方向同样持续失败。A000 MotionLCM第一个候选的肩线方向P95为16.27°，右肩位置P95为5.92 cm，骨盆方向P95为6.33°。这些是模板身体上的F−D诊断，不是Andy实测人体误差。
- 当前A001 OmniControl的拟合进程约占一个完整CPU核，已运行约30分钟并继续生成候选。电视保持运行；调度仍为13个电视活跃槽及1个Andy槽。

因此，独立头胸评分和HTML更新占比较小。主要计算支出来自完整身体拟合及协调候选的搜索；评分目标达标与全身D-only提前接受是两种判定，不能混用。

## 后续边界

本次只分析，原冻结运行继续，不修改阈值、候选顺序或已有结果。若建立专用头胸路径，应先在开发资料声明头胸观测契约及模板上下文的作用，冻结独立版本的D-only选择/停止规则，再测试。当前R验收结果只能提供分析证据，不能成为运行时挑选候选的依据。增加Andy并发可改善吞吐，但不会消除每路全身搜索成本，且需在总并发14以内重新分配。
